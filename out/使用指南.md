# Warp - 使用指南

> 生成时间: 2026-11-17
> 基于: 仓库 README.md / AGENTS.md / FAQ.md / CONTRIBUTING.md / script/ 实测内容

## 1. 项目简介

Warp 是一个**源自终端的智能体开发环境（Agentic Development Environment）**：既有内置编码智能体（Agent Mode），也可接入第三方 CLI 智能体（Claude Code、Codex、Gemini CLI 等）。本仓库是 Warp 的**客户端开源代码**（服务端、Drive 后端、Oz 编排层不在其中）。

- GUI 桌面应用（`app/` crate，GPU/WGSL 渲染）
- 无头 TUI 前端（`crates/warp_tui`，cell-grid 字符渲染）
- 两者共享 `warp_core` / `warpui` 核心

## 2. 快速开始

### 2.1 环境要求

| 要求 | 版本/说明 |
|------|-----------|
| Rust 工具链 | 1.92.0（`rust-toolchain.toml` 固定，含 rustfmt / clippy / rust-analyzer） |
| 操作系统 | macOS、Linux、Windows 均受支持 |
| Windows 额外依赖 | MSVC 构建工具（`script/windows/install_build_deps.ps1` 自动安装） |
| 测试运行器 | cargo-nextest（`./script/install_cargo_test_deps`） |

### 2.2 初始化与安装

```bash
git clone https://github.com/warpdotdev/warp.git
cd warp

./script/bootstrap        # 平台相关环境准备（Windows 上跑 script/windows/bootstrap.ps1）
```

`bootstrap` 同时会按 `skills-lock.json` 安装/更新公共 agent skills（可用 `--skip-common-skills` 跳过，或设 `WARP_SKIP_COMMON_SKILLS_INSTALL=1`）。

### 2.3 构建与运行

```bash
# GUI 桌面应用（默认 features=gui）
cargo run                 # 等价于 ./script/run
./script/run --release    # 发布模式

# 无头 TUI 前端
./script/run-tui

# 打包 .app（GUI）
cargo bundle --bin warp
```

`./script/run` 会自动判断渠道：若 PATH 上有 `warp-channel-config`（内部仓库）则构建 `warp`（local 渠道），否则构建 `warp-oss`（OSS 渠道）。macOS 走 `.app` bundle 流程，Linux/Windows 直接 `cargo run`。

### 2.4 连接本地 warp-server（开发调试）

```bash
# 默认端口 8080
WITH_LOCAL_SERVER=1 ./script/run

# 自定义端口 8082
WITH_LOCAL_SERVER=1 SERVER_ROOT_URL=http://localhost:8082 WS_SERVER_URL=ws://localhost:8082/graphql/v2 ./script/run
```

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `SERVER_ROOT_URL` | `http://localhost:8080` | HTTP 端点 |
| `WS_SERVER_URL` | `ws://localhost:8080/graphql/v2` | WebSocket 端点 |
| `WITH_LOCAL_SERVER` | - | 置 1 启用本地 server 连接 |

## 3. 测试、Lint 与格式化

```bash
cargo nextest run --no-fail-fast --workspace   # 全量测试（nextest 并行）
cargo nextest run -p <package>                  # 单包测试
cargo test --doc                                # 文档测试

cargo clippy -p <package> --all-targets --tests -- -D warnings   # 定向 Clippy

./script/format                                 # Rust 格式化
find . -name "*.wgsl" -exec wgslfmt {} +        # WGSL shader 格式化
./script/presubmit                              # 完整预提交（仅在明确要求时运行）
```

**实施验证顺序**（来自 AGENTS.md，agent/贡献者通用）：编辑期间只跑最小定向 `cargo check`/`cargo nextest` → 代码完成后跑相关测试 → Clippy/lint → 最后统一跑一遍所有适用的格式化工具 → 开 PR（格式化后不再重跑测试）。完整 presubmit 仅在明确要求时执行，其余交给 CI。

## 4. 二进制与渠道

`app/Cargo.toml` 定义了多个 `[[bin]]`，对应不同发布渠道（代码相同，仅 bundle 图标/应用名/渠道配置不同）：

| 二进制 | 渠道 | 说明 |
|--------|------|------|
| `warp-oss` | OSS | 默认运行目标（default-run），开源构建 |
| `warp` | local | 本地开发构建 |
| `stable` / `preview` / `dev` | stable/preview/dev | 官方发布渠道（内部构建） |
| `integration` | - | 集成测试专用 |

## 5. 主要功能面（面向使用者）

| 功能 | 说明 | 代码位置 |
|------|------|----------|
| 终端与 Shell 管理 | PTY 会话、shell 集成（bash/zsh/fish/pwsh 引导脚本） | `app/src/terminal/`、`crates/warp_terminal/`、`app/assets/bundled/bootstrap/` |
| Blocks 模型 | 命令/输出成块的终端范式 | `crates/warp_terminal/`、`app/src/terminal/` |
| Agent Mode | 内置 AI 编码智能体、工具调用、diff 应用 | `app/src/ai/`、`crates/ai/` |
| 第三方 CLI 智能体 | Claude Code / Codex / Gemini CLI 接入 | `app/src/coding_entrypoints/` 等 |
| Warp Drive 云同步 | 对象跨设备同步、会话共享 | `app/src/drive/`、`crates/cloud_objects/` |
| Workflows | YAML 工作流（warp-workflows 依赖） | `app/src/workflows/` |
| 命令补全 | Fig specs + 自研补全引擎 | `crates/warp_completer/` |
| MCP | Model Context Protocol 客户端/服务器 | `crates/mcp/` |
| 设置系统 | settings crate + JSON schema 生成 | `crates/settings/` |

### 5.1 Feature Flags

Warp 用**编译期 cargo feature**（`app/Cargo.toml` 中 600+ 个 feature，default 列表极长）+ **运行时 FeatureFlag**（`crates/warp_core/src/features.rs`，含 `DOGFOOD_FLAGS` / `PREVIEW_FLAGS` / `RELEASE_FLAGS` 分层放量）双轨控制功能。社区贡献的功能默认走编译期 feature。

## 6. 配置说明

### 6.1 用户级配置

- 应用设置：应用内 Settings UI；`crates/settings` 支持从设置 JSON schema 生成文档（`--generate-schema`）。
- 终端配置文件、主题、快捷键均在 Settings 中管理；`warp_packs` feature 支持主题/配置包分发。
- `.warp/` 目录（仓库内有 `.warp/skills`、`.warp/workflows`）：项目级 Warp 工作流与技能。

### 6.2 开发常用环境变量

| 变量 | 说明 |
|------|------|
| `WARP_COMMON_SKILLS_INSTALL_TARGET` | bootstrap 安装 skills 的目标（project/global），非交互流必设 |
| `WARP_SKIP_COMMON_SKILLS_INSTALL=1` | 跳过 skills 安装检查 |
| `WARP_COMMON_SKILLS_REF` | 测试远程 common-skills 分支 |
| `WARP_CLOUD_MODE_DEFAULT_HOST` | `./script/run --host-id` 透传 |

## 7. 常见问题

### Q: 客户端是完全开源的吗？
A: 客户端开源：应用与大部分 crate 为 AGPL v3，UI 框架 crate（`warpui_core`、`warpui`）为 MIT。服务端、Drive 后端、Oz 不在本仓库。

### Q: 不登录能用吗？
A: 部分功能可完全本地运行；Drive 同步、托管模型智能体、团队功能需要 Warp 后端（或本地 warp-server）。

### Q: 如何贡献代码？
A: 先提 issue；维护者打 `ready-to-spec`（先写规格 PR：`specs/GH<issue>/product.md` + `tech.md`）或 `ready-to-implement`（直接代码 PR）标签。PR 由 Oz（智能体）初审 + 人类专家复审。

### Q: PR 卡住没 review 怎么办？
A: 推送修复后评论 `/warp-agent-review`（每 PR 至多 3 次），或在 issue/PR 上 @oss-maintainers。

### Q: Windows 上构建需要注意什么？
A: 用 `script/windows/bootstrap.ps1` / `install_build_deps.ps1` 准备 MSVC 工具链；注意仓库对 MAX_PATH 的处理（Cargo profile 使用短别名 `rlto`/`rcli` 规避 255 字符路径限制）。详见《Windows兼容性分析.md》。

## 8. 目录速查

```
├── app/                  # GUI 桌面应用（composition root，AI/终端/设置/Drive 等全部表面）

```
